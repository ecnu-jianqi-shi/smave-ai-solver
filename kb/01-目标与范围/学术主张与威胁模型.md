# 学术主张与威胁模型

## 中心研究问题

在同一数值问题存在经典、学习型、迭代和直接法候选时，如何根据请求特征联合选择
专家、工作预算和执行顺序，最小化包含 candidate、transfer、correction、原方程验收
与数值续接的完整求解成本，同时保证每个成功返回的结果都满足原方程 residual、
约束、分支或离散缺陷合同？

研究对象是完整的数值求解闭环：

```text
EquationAssessment
  → request-conditioned expert--budget prediction
  → exact bounded SolvePlan
  → candidate/corrector
  → original-equation numerical acceptance
  → next numerical path or terminal classical solver
```

这里的 `gate` 仅指原方程数值验收。候选失败后从原始请求状态继续下一条数值路径，
统一称为“数值续接”；`fallback` 只作为历史代码或指标字段名保留。

## 三项核心贡献主张

### C1：完整成本的类型化专家级联

将异构求解建模为具有 reach probability 的类型化候选级联，显式计入候选、搬运、
校正、验收与 terminal numerical-continuation 成本；在 action 统计与顺序无关的条件下，以
cost-per-acceptance 规则排序，并使用 exact bounded dynamic programming 联合选择
`(expert, work budget)` action。

**可证伪条件：** 排序规则与 exhaustive enumeration 不一致，或 exact DP 在相同
action 合同下不能复现 exhaustive optimum，则 C1 不成立。

### C2：候选、校正与原方程验收协同

学习模型只产生候选、初值、预条件作用或近似算子输出；family-specific corrector
决定是否值得继续修正，原方程 residual、约束、事件、互补或离散缺陷决定是否接受。
候选失败只影响完整成本和求解完成率，不能改变成功返回的数值合同。

**可证伪条件：** 任一成功返回路径绕过原方程验收，gate 失败后状态污染后续经典
路径，或不同入口执行不同数值合同，则 C2 不成立。

### C3：请求条件 expert--budget 路由

Router 使用查询前可得的结构、数值状态、右端项和容差特征，联合预测 action 成本与
通过概率，再由同一 exact DP 生成计划。主要评价是 held-out complete-cost regret、
校准误差、计划多样性和 feature sensitivity，而不是易受计时噪声影响的 winner label
accuracy。

**可证伪条件：** 在 matrix-ID-disjoint held-out 集上，请求条件策略不能优于静态
profile 和最佳固定 action，或其收益依赖训练/测试矩阵重叠，则 C3 不成立。

## 不主张的内容

- 不主张提出普适领先的新神经算子、基础模型或全新数值分析理论；
- 不主张所有 PDE、DAE、Modelica 或 Simulink 模型都能加速；
- 不主张受限离散子系统等价于完整 PDE、DAE 或 hybrid trajectory；
- 不主张有限样本的零 gate mismatch 等于未来永不错误接受；
- 不主张未测硬件、未测规模或未测方程族具有相同性能；
- 不主张所有 workload 达到 `100×`，也不以 fallback-only 案例制造速度比。

## 研究与评审边界

论文只因求解器方法、数值正确性、完整路径成本、实验设计和证据强度而得分或扣分。
所有论文贡献、审稿条件、阶段 gate 和下一阶段任务都必须映射到上述求解器主张或其
可证伪证据，不能用与核心科学问题无关的工程能力替代方法创新。

本文的 matrix-ID-disjoint、collection-group-disjoint 和 independent trial 均是实验
设计或统计术语，用于防止数据泄漏并界定有效样本数，不描述求解器部署架构。

## 假设与实验问题

| 编号 | 可证伪假设 | 所需证据 |
|---|---|---|
| H1 | 完整成本计划优于最佳固定 action 和静态 profile | 同请求真实 action attempts、held-out regret、bootstrap 区间 |
| H2 | 原方程 gate 能拒绝观察到的错误候选且不污染后续路径 | 故障注入、逐 attempt residual、原状态重跑、gate mismatch 统计 |
| H3 | 请求条件特征能稳定改变有利计划 | matrix-disjoint split、feature ablation、plan diversity、feature-changed fraction |
| H4 | correction/work budget 是独立于 expert identity 的关键决策量 | 多预算 action、接受率/成本曲线、预算消融、terminal fallback 保留 |
| H5 | action 交互和成本尾误差会限制独立 action 模型 | order/interference 实验、median/P95/max cost error、tail-aware 对照 |

## 必需对照与消融

每个请求条件路由实验至少包括：

1. 调优后的经典求解器基线；
2. 每个兼容 expert 的全部预算 action；
3. 最佳固定 action；
4. 静态 family/profile 策略；
5. 请求条件策略；
6. held-out exhaustive oracle；
7. exact DP 与 exhaustive 一致性；
8. size-only、RHS-only、tolerance-only 与完整特征消融；
9. action 顺序或共享 setup 交互；
10. 全部失败、拒绝、fallback 与负结果。

## 当前证据边界

- 生产线性服务已经执行 PCG-IC(0)、PCG-Jacobi、GMRES-ILUT、GMRES-ILU(0)
  和兼容直接法的 Router-selected work budget；每次 attempt 重新计算原矩阵 residual。
- `reproduce-request-conditioned-joint-route` 已验证请求条件成本/通过率模型、exact DP、
  calibration、regret 和 feature-sensitive plans，但当前 action observations 仍来自受控
  组合，不足以证明真实公共 solver portfolio 上的决策收益。
- SuiteSparse 已有公共矩阵与生产后端执行基础，但尚未完成 matrix-ID-disjoint 的
  train/calibration/held-out expert--budget 策略实验。
- PDEBench、HINTS 与当前非线性/operator 实验提供机制、性能和负结果证据，但不能
  替代真实公共稀疏组合上的 C3 验证。

## 当前 P0

在 matrix-ID-disjoint SuiteSparse split 上执行真实生产 portfolio：

- 对每个矩阵构造 deterministic manufactured requests 与多容差请求；
- 运行全部兼容 PCG/GMRES/direct expert--budget actions；
- 冻结 train/calibration/held-out matrix IDs；
- 报告 conditioned/static/fixed regret、exact oracle、cost tail、Brier/ECE、计划多样性、
  feature ablation、action interaction、attempt 顺序、原方程 gate mismatch 和 terminal
  fallback；
- 保留所有失败和不优于 control 的负结果。

## 威胁模型

### 数值正确性

- residual、约束、事件或离散缺陷 callback 定义错误；
- candidate 或 corrector 产生 NaN、错误分支、错误根或状态污染；
- gate 缩放、容差或 backward-error 口径与比较基线不一致；
- direct、Krylov 与 caller fallback 使用不同原问题数据。

### 路由模型

- action cost/pass 统计受前序 action、cache、setup 或线程状态影响；
- cost tail error 被 median 指标掩盖；
- 特征泄漏 matrix identity、oracle label 或 held-out timing；
- calibration split 与 held-out matrix 不独立；
- exact winner label 在实用等价 action 间随计时噪声变化。

### 外部有效性

- 小型、规则或 manufactured 问题不能代表工业稀疏系统；
- 单一矩阵族、容差或硬件不能代表跨族泛化；
- 只报告共同成功样本会隐藏 no-common-success 和失败保留；
- 学习型 baseline 的简化重实现不能替代其官方代码或公开权重。

## 证据映射与未完成项

| 主张 | 当前证据 | 未完成项 |
|---|---|---|
| C1 | cascade ordering、joint route-budget exact-DP/exhaustive checks | action interaction 与共享 setup 模型 |
| C2 | family-specific gate、attempt trace、terminal fallback、fault tests | 更困难非线性/DAE/事件候选与外部 learned solver |
| C3 | 5,760 action observations 与 request-conditioned held-out evaluation | matrix-ID-disjoint SuiteSparse production portfolio |
| H4 | production `work_iterations`、budget validation、低预算拒绝与全预算 terminal path | 公共矩阵上的多预算 break-even 曲线 |
| H5 | 当前 cost median/P95/max 与 retained negative results | tail-aware/interaction-aware route comparison |

论文结论只依据已执行的求解器机制与数值实验；兼容性和工程支撑不进入贡献、评分或
下一阶段必做任务。
