# 分阶段路线图

> 本页仅保留历史记录，已被仓库根目录 `GOAL.md` 和
> [[01-目标与范围/学术主张与威胁模型]] 取代。工程化内容不再作为研究 Phase、
> 论文贡献、评分条件或下一阶段任务。

## Phase 0：源级编译与基准（2–3 周）

- 通过 OpenModelica API 导出 flattened model/BackendDAE 信息；
- 建立最小 equation IR、incidence graph 与 BLT/SCC；
- 选一个非线性代数环和一个小型 DAE 基准；
- 固化 block residual、缩放和 fallback 接口。

**退出条件：** 可从源模型定位方程块、生成 residual/Jacobian，并调用原 block solver。

## Phase 1：可验证 Block Solver MVP（3–5 周）

- 采集原求解器 block 调用上下文、收敛解和迭代轨迹；
- 训练 MLP warm-start/candidate solver，组合少量标签与 PINN 方程残差；
- 对变量、方程和损失梯度进行量纲缩放与自适应平衡；
- 用原方程 residual gate 验收每次候选；
- 失败时调用原 block solver 并记录反例；
- 报告 fallback 率、迭代减少和端到端加速。

**退出条件：** 不降低原收敛标准，且在至少两个方程块上减少平均迭代或墙钟时间。

## Phase 2：学习增强经典求解器（4–8 周）

- 为重复 Jacobian 序列实现前一步解/小网络 warm-start；
- 实现 NeuralPCG/GNP 风格的预条件器作用专家；
- 对规则多尺度线性块实现 UGrid 风格 learned multigrid 实验；
- 保持 CG/GMRES/Newton 原 residual 和经典 ILU/AMG fallback；
- 对高密度或显式 Jacobian 内存高的 smooth nonlinear block，使用 JFNK directional-AD `J·v` 与 O(n) diagonal preconditioner；不可微 entry 局部 FD，弱对角局部 identity，最终仍由原方程 residual gate 验收；
- 分离 setup、apply、iteration、gate 和设备传输时间；
- 建立规则型编译期 Router，在经典、预条件器和 multigrid 专家间选择。

**退出条件：** 至少一个大型线性 SCC 在同硬件、同 residual 下获得稳定端到端加速，P99 不回归且原收敛率不下降。

经典安全级联另以 `reproduce-nonsymmetric` 覆盖非对称 GMRES+ILUT/ILU(0) 与 `sparse-ordered-threshold-pivot-cpu-v2`。后者使用确定性 greedy AMD 列顺序和 scale-relative threshold row pivot；`10^-16` 量级 5×5 hub matrix 的直接证据要求最大解误差约 `2.22×10^-16`、非 identity order `3,4,0,1,2`、symbolic fill edge `5→0` 且双运行逐字节一致。零首 pivot Runtime fixture 还要求两种无 pivot ILU 路径拒绝后由 v2 经原 residual gate 接受、零 full fallback。该证据不代表 matching/equilibration、supernodal/multifrontal、KLU/UMFPACK 或工业规模性能。

当前 C++20 CPU 基线以 10×10 Poisson 的 100 unknown 单 SCC 关闭该条件：Runtime 对严格证明的 context-independent linear matrix 做 RHS-only 重装缓存，64 个 held-out 场景、20 次交替重复形成 1,280 个配对完整 Runtime 样本，learned-PCG 将 Krylov 平均迭代 `13→1`；固定种子 2,000 次 bootstrap 的配对中位 speedup `95%` 下界大于 1，P99 不回归，配对胜率超过 `95%`，且零失败、零错误接受、零 full fallback。该证据不外推到工业稀疏规模、GPU/NPU 或一般 AMG/ILUT。

## Phase 3：反例引导与证明域（4–8 周）

- residual 最大化搜索困难上下文；
- 加入 residual-based adaptive refinement 和增广拉格朗日约束；
- 区间细分并建立可直接接受的 verified cells；
- 处理多根、分支连续性和 Jacobian 退化；
- 对无法验证区域保持 warm-start-only 模式。

**退出条件：** 反例闭环稳定，验证域可复现，域外或困难点继续经典求解路径。

当前 C++20 基线以 `reproduce-phase3` 对 `x²=p²` 的参数域关闭受限退出条件：固定 45 个 probe 将 `[-1,1]` 细分为 6 个 verified cells，`p=0` Jacobian 退化点按上下文去重为单一反例；重复训练/验证逐字节一致。域内点可使用 learned warm-start，退化点和域外点不执行 learned expert并继续经典 portfolio。该证据不外推到高维全局搜索、一般多根/分支连续性、区间证明或任意 Jacobian 退化。

## Phase 4：方程基础表征与学习 Router（6–10 周）

- 借鉴 PDEformer/PROSE，将 AST、方程图、Jacobian 图和数值画像编码；
- 建立 equation fingerprint 与专家相似性检索；
- 通过专家竞赛生成 Router 监督标签；
- 训练运行期成本/通过率/风险预测器；
- 引入 Research → Shadow → Warm-start → Corrected 专家生命周期；
- 对新方程验证已有 family expert + instance adapter 的适配成本。

**退出条件：** 学习 Router 在保留测试方程族上不增加错误接受，并在端到端成本上优于固定专家顺序和规则基线。

当前 C++20 基线以 `reproduce-phase4` 对 5×5→6×6 Poisson 家族关闭受限退出条件：源实例全专家竞赛迁移可用的内建胜者，64 个 held-out 场景、20 次交替重复形成 1,280 个固定规则/校准策略配对完整 Runtime 样本。固定种子 2,000 次 bootstrap 的配对中位 speedup `95%` 下界通常约 `1.09×` 且高于 `1.01` 门槛；64/64 成功、零 full fallback/失败/gate mismatch/错误接受，单侧 `95%` 错误接受率上界低于 `5%`。P99只保留遥测。该证据不外推到学习型 GBDT/MLP/GNN Router、跨结构 learned artifact 权限或广泛方程家族。

## Phase 5：神经算子摊销专家（6–12 周）

- 只选择调用量足以达到 break-even 的稳定方程族；
- 比较 FNO、geometry-aware operator 和轻量 latent operator；
- 区分 full-state 与 QoI-only 专家权限；
- 将 operator 输出接入 residual gate、误差估计和 Newton corrector；
- 在项目 `0.01%` 门槛下重新测量，不能继承论文百分比误差数字；
- 未达到 direct 条件时只用作筛选、初值或低保真层。

**退出条件：** 至少一个 many-query 方程族证明训练 break-even、端到端收益和无错误接受的校正路径。

当前 C++20 基线以 `reproduce-phase5` 关闭受限退出条件：10×10 Poisson 使用 16 个标签训练 rank-1 latent Operator，64 个 held-out 场景、20 个 batch 形成 1,280 个请求；64/64 validation 成功、零 full fallback/失败/错误接受，校正 trace 全为 `CORRECTED_ACCEPT` 且 `direct=0`，单侧 `95%` 错误接受率上界低于 `5%`。原始 candidate 与校正后 QoI 均满足 `10^-4` 门槛，在线和 10,000 次调用摊销均加速，break-even 已通过。当前 Release 观测在线/摊销约 `1.27×`、break-even 约 120 次查询。该证据不外推到 FNO/Geo-FNO/GINO、GPU、几何变化或非线性 DAE。

## Phase 6：事件与模型组（6–10 周）

- 保存事件日志并实现事件感知采样；
- 分模式动力学、guard 和 reset 模型；
- OMSimulator/SSP 或配置驱动的多 FMU 组合；
- 分层代理与接口误差分析。

**退出条件：** 事件漏检率、时刻误差和模型组耦合误差达到门槛。

当前 C++20 基线以 `reproduce-phase6` 关闭受限退出条件：自包含模型组按确定顺序提交，plant 单节点进入原 solver fallback，连接误差为 0且 fallback trace 可审计；受限原生 `.slx` 适配器支持标量 Constant/Gain/Sum/UnitDelay/Switch、Branch、最多 64 层同 rate SubSystem 端口组合，以及每个 `System` 内唯一解析并消除的 scalar local Goto/From。递归层级与本地 tag fixture 均双运行逐字节一致，重复 connector Port、重复 Goto tag、未解析 From tag 和 connector/tag chain 必须拒绝。`reproduce-ssp` 以两个真实 FMI 2 Co-Simulation 实例、FMI 2→FMI 3 混合实例、degC→K 后执行 `0.5*x+1` 的连接变换实例、上游 FMI 3 通信点事件实例及 FMI 3 time event→FMI 2 variable-step 实例覆盖 SSP 1.0 feed-forward master：稳定 step order，基础终点 `A.y=2.3,B.y=4.9`、变换终点 `B.y=277.75`、事件后终点 `A.y=22.3,B.y=44.9`；time event 在 `t=0.15` 形成第 5 个通信点，报告 1 次内部切分、1 个 time event、2 次 event mode、2 次离散迭代，且双运行逐字节一致。未授权执行、反馈环、connector/FMI metadata 不匹配、未声明 event mode、early return、任一组件缺少可变步能力、BaseUnit 维度不兼容和 SSD/FMU unit 定义不一致均拒绝。固定采样事件 report v2 在 3 个候选中接受 1 个正确候选、拒绝 2 个错时/错序候选，权威事件 `MISSED_EVENTS 0`、`EVENT_RECALL 1`，时刻/reset 误差均为 0。另以 `reproduce-dae-grazing` 覆盖受限 semi-explicit index-1 DAE 的单个光滑孤立 grazing root。上述证据不外推到统计性多事件漏检率、完整 Event Expert、非孤立/平坦 guard、接触互补、完整 Simulink 语义、带反馈迭代/跨实例 superdense 事件固定点/rollback/异步 deadline 的一般 SSP master 或异步多 rate。

产品接口侧另以 `reproduce-fmi2-event` 覆盖受限 FMI 2 Co-Simulation 内部事件：FMU 在 `t=0.15` 返回 `Discard`，宿主读取并门禁 `lastSuccessfulTime`、切分剩余宏步后继续到原通信点，双运行逐字节一致；零进展 `Discard` 被拒绝。该事件切分证据不支持无 status query 的事件、通用 rollback 协商或多 FMU master。

`reproduce-fmi-me-grazing` 进一步用真实 C++20 FMI 2/3 Model Exchange 动态库覆盖同号 event indicator 的单个光滑孤立 grazing root。宿主从宏步起点重复 RK4，以黄金分割最小化 `|indicator|`，在 `10^-8` residual/prominence 门禁后进入各版本事件固定点；首步 save/restore/replay 使每版报告 `MODEL_EXCHANGE_ROOTS 2`、`MODEL_EXCHANGE_GRAZING_ROOTS 2` 且 replay error 为 0。单元测试另以最小值保持 `0.01` 的近切触 fixture 要求零 root。该证据不代表非孤立/平坦 indicator、单步多极值或第三方 FMU 广泛兼容性。

`reproduce-fmi-me-nominal` 在相同两版动态库上覆盖 continuous-state nominal change：事件固定点声明更新后，宿主调用标准 nominal API，要求固定 state count 下所有 nominal 有限且严格为正；双运行均报告 2 次 replay 对应更新、最小/最大 nominal 为 2 且输出逐字节一致。单元测试另让两版返回 nominal 0，必须在继续积分前失败。该证据不包含运行期 state count 变化或 nominal 对误差控制器的自适应步长调节。

`reproduce-fmi2-async` 进一步覆盖受限 Pending：声明 `canRunAsynchronuously=true` 的 FMU 返回 Pending 后，宿主轮询 `doStepStatus`、核对由 worker thread 发出的 `stepFinished` 并报告跨线程回调、继续原通信网格；永久 Pending 在配置期限后调用 `CancelStep` 并失败。未声明能力和缺失回调均拒绝。该证据不代表并发异步 master、跨实例 deadline 协调或任意第三方回调线程模型保证。

## 历史工程记录（非研究 Phase）

以下内容只保留既有回归背景，不构成当前研究优先级。

- Simulink/商业 Modelica 工具适配器；
- surrogate FMU 导出；
- 模型 registry、数据版本、审计与 CI；
- GPU/CPU 批量推理、C++ runtime；
- 超域诊断与 FMU 兼容回退；
- Expert ABI 与 Router/专家兼容 registry；
- 基于调用热度的专家加载、batch bucket 和 CPU/GPU/NPU 调度。

当前 C++20 工程化基线新增 `reproduce-residency`：单进程 CPU residency manager 使用显式字节预算、最小调用次数和 `(heat,last_used,version)` 确定性 LFU/LRU tie-break；同热候选不得逐出 resident，更热候选可逐出较冷版本。Runtime 在 Registry 兼容性通过后执行驻留门禁，并将 load/hit/reject/eviction 写入 trace；冷 expert 被拒绝时仍由原 block solver 成功结束，达到热度后加载并在后续 solve 命中。证据明确报告 `GPU_NPU_BACKENDS 0`；这不是实际权重搬运、动态加载、NUMA、GPU/NPU kernel、并发 batch queue 或跨进程 cache 实现。

`reproduce-data-registry` 进一步覆盖本地数据版本基线：两个嵌套场景文件生成以 manifest SHA-256 为版本的不可变快照，重复导入得到同一版本；权威 store 校验逐文件大小、摘要和完整文件集。负向测试只复制 store 并篡改副本 payload，要求校验失败，再复验原 store 仍有效。Phase 1 的 Coupled 与 CubicCoupled 训练/evaluation 分别使用独立快照，Affine v2 artifact 与 certificate v2 共同绑定训练 lineage；通用 Performance v2 将完整落盘统计与 evaluation lineage 纳入 hash。Phase 2 的 linear preconditioner v2 与 `reproduce-multigrid` 的 multigrid v3 同样绑定各自训练快照，机器 verifier 比较 artifact/certificate dataset version，单元测试拒绝重新 seal 后的错版本 certificate；`reproduce-dae-multigrid` 则从同一快照生成 DAE wrapper v2 与 Learned Multigrid hierarchy v3，两层 artifact hash 均绑定相同 dataset id/version/manifest hash，并以单元测试拒绝任一侧重新 seal 后的 lineage 分叉。Phase 4 将 source competition 与 heldout family 场景固化为两个独立快照：Competition v4 绑定 source lineage，Family Router Evaluation v3 同时绑定 source/heldout lineage 与两份 competition hash，heldout validation 复用同一已验证快照。Phase 7 发布复现将 16 个 Operator 训练场景和 64 个 validation 场景固化为另两个独立快照：Latent Operator v2 与 certificate v2 共同绑定训练 lineage；Validation v3/Operator Benchmark v2 则绑定独立 validation lineage，再进入 shadow/canary、签名 release store、回滚和状态复验。该证据仍不包含并发 writer、远端对象存储、访问控制或生产数据治理。

## 关键依赖顺序

`方程 IR → 原方程数值 gate → warm-start → 神经预条件/多重网格 → PINN 反例闭环 → 方程基础表征与 Router → 神经算子摊销专家 → 事件方程`。研究顺序只由求解器机制、数值正确性和完整路径性能决定。

`reproduce-fmi-me-scalar-types` 以真实 C++20 FMI 2/3 Model Exchange 动态库覆盖数值/Boolean 标量 I/O，并保留连续状态和首步 state replay。两版双运行逐字节一致，fractional/越界 integer、非法 Boolean、Float32 溢出与不安全 64 位整数均被拒绝。

该标量 I/O 证据现扩展为 FMI 2 Real/Integer/Boolean/Enumeration 与 FMI 3 Float32/Float64、全部 8/16/32/64 位有符号/无符号整数、Boolean/Enumeration。每个 FMI 3 数值类型调用对应标准 Get/Set ABI；Enumeration 分别复用 FMI 2 Integer 和 FMI 3 Int64 通道。整数输入除类型范围外还要求从 CLI double 精确表示，64 位整数输出超出 IEEE-754 安全整数域会拒绝，防止报告静默舍入。

`reproduce-fmi-me-scalar-types` 现进一步覆盖 FMI 2/3 标量 String。CLI 通过可重复的 `--string-input name=value` 传入字符串，宿主调用对应版本 `SetString/GetString`，在下一次 FMI 调用前复制返回指针，并以 `SMAVE_FMI_SMOKE_REPORT 2` 的确定性 `STRING_SAMPLE` 行记录输出。首步 save/restore/replay 对字符串使用逐值完全相等门禁；把 String 输入绑定到数值变量会硬拒绝。原数值-only 报告继续保持 v1。

FMI 3 标量 Binary 现由同一复现目标覆盖。CLI 接受可重复的 `--binary-input name=hex`，严格拒绝奇数长度、非十六进制和 FMI 2 使用；宿主通过标准 `SetBinary/GetBinary` ABI 传递字节与长度，在下一次 FMI 调用前复制最多 16 MiB 的输出，并以小写十六进制 `BINARY_SAMPLE` 记录。非文本字节 `00a5ff→ff5a00`、空 Binary、逐字节 state replay 和双运行确定性均有机器门禁。

同一复现目标现覆盖固定 extent 与冻结结构参数 extent 的 FMI 3 数值、Enumeration、Boolean、String 和 Binary 数组。`SMAVE_FMI_BLACKBOX_4` 保存每一维的固定 extent 或动态 extent value reference；动态 descriptor 仅在其引用 `variability=fixed` 的 unsigned scalar `structuralParameter` 且提供正整数 `start` 时解析，其他情况硬拒绝，不猜测运行期形状。数值与 Boolean 数组通过 `--array-input name=v1,v2,...` 传入；String/Binary 数组通过逐元素重复的 `--string-array-input name=value` 与 `--binary-array-input name=hex` 传入，因此空值及含逗号/等号的 String 不依赖转义分隔符。各类型 Get/Set ABI 使用 value reference 列表和完整连续 `nValues`；报告分别以 `ARRAY_SAMPLE`、`STRING_ARRAY_SAMPLE` 与 `BINARY_ARRAY_SAMPLE` 保存，并在下一次 FMI 调用前复制所有返回指针。fixtures 覆盖数值/Boolean 代表性通道、String 空值和标点、Binary 空值与非文本字节、首步逐元素 replay、双运行一致性，以及数量、数值范围、hex 格式和不可解析动态维度门禁。Clock 按规范仅为标量，使用独立 `SetClock/GetClock` ABI，并与 Boolean 一样要求输入严格为 `0/1`、输出归一化为 `0/1`；初始化离散固定点后再用 `GetIntervalDecimal/GetShiftDecimal` 读取 interval、shift 和 qualifier，验证有限正 interval 及 `0 <= shift < interval`，并写入 smoke report。该证据不驱动模型分区，也不等同于 Scheduled Execution。剩余数组边界仅为运行期结构参数重配置。

`reproduce-fmi-se` 以真实 C++20 FMI 3 动态库覆盖单 Clock 与多周期双 Clock。双 Clock 在 `t=0` 和 `t=0.5` 同刻激活时，以 `slow(priority=10)` 先于 `fast(priority=20)`，其余同优先级情况保留 value reference/name 稳定 tie-break；重复报告逐字节一致。门禁同时拒绝周期不匹配、缺失 Clock、缺失 priority 和不平衡回调。该证据不外推到 Clock 依赖图、并发抢占、动态 priority/周期重配置、aperiodic Clock 或多 FMU 调度。

基础 FMI 3 Model Exchange 与 Co-Simulation fixture 现声明 state 序列化能力。宿主把首步保存的 state 序列化为 32-byte 自包含 payload，释放原 handle，反序列化为新 handle 后执行恢复和完整 replay；双运行报告逐字节一致。机器门禁同时拒绝序列化能力缺少基础 state 能力和损坏 payload。该切片不覆盖事件或异步 Co-Simulation，也不承诺 serialized state 跨 FMU 版本、跨平台或长期存储兼容性。

基础 FMI 2 Model Exchange 与 Co-Simulation fixture 同步声明 `canSerializeFMUstate=true`，分别使用 35-byte 与 32-byte payload，并经过相同的新 handle replay 与负向门禁。当前 FMI 2/3 serialized-state 退出证据覆盖基础 Model Exchange 与基础 Co-Simulation；event-mode、early-return、Pending 等事件或异步 Co-Simulation 仍不在该退出证据内。
